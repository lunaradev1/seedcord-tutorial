Now that you're introduced to this tutorial, let's start it off by answering one simple question: "What is seedcord?"

## What is seedcord?

[Seedcord](https://seedcord.org) (stylized as seedcord) is a Discord framework developed by [materwelon](https://github.com/materwelonDhruv), built to be type-safe across boundaries. An invalid handler route will throw at compile-time (thanks to TypeScript's static type checking) rather than at runtime when the code is actually being interpreted. You can also utilize [Vite](https://vite.dev) plugins (explained later), deploy your bot to the edge (like on [Cloudflare](https://cloudflare.com)), use it like a package (with full type safety!), and enjoy having a fully type-safe bot from end-to-end!

## Why use seedcord?

Most Discord frameworks are type-safe, but the type safety ends when you cross boundaries. For example, Sapphire doesn't really stay type-safe if you decide to separate your logic out of the classes. Plus, you'd have to register the command manually, losing valuable time you could've spent on debugging the logic. Let's see that in an example.

<Scrollycoding>

```typescript title="commands/ping.ts" showLineNumbers id="sapphire-ping-command"
import { ApplyOptions } from '@sapphire/decorators'
import { Command } from '@sapphire/framework'
import { MyCommandLogic } from '~/some/other/path'

@ApplyOptions<Command.Options>({})
export class PingCommand extends Command {
    public override async chatInputRun(interaction: Command.ChatInputCommandInteraction) {
        const someOption = interaction.options.getString('some-option')

        await new MyCommandLogic().run(interaction)
    }

    public override registerApplicationCommands(registry: Command.Registry) {
        registry.registerChatInputCommand((builder) =>
            builder
                .setName('ping')
                .setDescription('Check if the bot is alive')
        )
    }
}
```

<Step focus="8" mark="8">This option could be undefined, but you won't know until you run the bot.</Step>
<Step focus="3,10" mark="3,10">The types here have to match up, even if you change something here.</Step>
<Step focus="13-19" mark="13-19">You have to register the command manually, which is a pain and can be error-prone.</Step>
<Step mark="1-20">This file will compile successfully given that `~/some/other/path` exists, but if one of them has a runtime error, you won't know until you run the bot.</Step>

```typescript title="commands/ping.ts" showLineNumbers id="sapphire-ping-command-updated"
import { ApplyOptions } from '@sapphire/decorators'
import { Command } from '@sapphire/framework'
import { MyCommandLogic } from '~/some/other/path'

@ApplyOptions<Command.Options>({})
export class PingCommand extends Command {
    public override async chatInputRun(interaction: Command.ChatInputCommandInteraction) {
        const someOption = interaction.options.getString('some-option')

        // Gotta restart the bot after this gets added!
        const anotherOption = interaction.options.getString('another-option')

        await new MyCommandLogic().run(interaction)
    }

    public override registerApplicationCommands(registry: Command.Registry) {
        registry.registerChatInputCommand((builder) =>

}
```

<Step mark="10-11">On top of that, for every change you make, you'll have to restart your bot completely to see the changes, costing even more valuable time (and potentially getting you rate limited by Discord if you keep restarting for every development change).</Step>

## Why not seedcord?

Seedcord _can_ be a good option for your bot, but if you:

- Are wanting to use **JavaScript** instead of **_TypeScript_**
- **Don't need** _end-to-end_ type safety
- **Don't care about using** _ComponentsV2_ for displaying information by default
- Would rather use something a little **more _stable and mature_** (seedcord isn't 1.0 yet as of writing this!)
- Want **_prefix (message) commands_** (which requires a privileged intent and is **not** supported out-of-the-box by Seedcord)

Then Seedcord might not be for you. In that case, just close this tab and move on. **No need to cry over spilled milk!**

## Prerequisites

This tutorial will assume that you have:

- Basic programming knowledge (any language is fine, even JavaScript)
- Basic [TypeScript](https://typescriptlang.org) knowledge (namely: syntax, types, [generics](https://www.typescriptlang.org/docs/handbook/2/generics.html), and [decorators](https://www.typescriptlang.org/docs/handbook/decorators.html))
- Knowledge of [discord.js](https://discord.js.org), or [another Discord framework/library](https://github.com/apacheli/discord-api-libs) (preferable, but not absolutely required for all cases)
